# AdamN — نظام إدارة الحضانة (NMS)

> **AdamN NMS** هو نظام إدارة حضانات كامل (Full-Stack) يعمل **محليًا على جهازك**، ويخزّن كل البيانات في **ملف واحد اسمه HDANA** تستطيع نقله أو نسخه أو وضعه على أي مسار — ويبقى البرنامج مرتبطًا به تلقائيًا بعد أول ربط، حتى لو نقلته من مكان لآخر.

Arabic-first • Responsive • Offline • Single data file • Bilingual (عربي / English)

---

## 1) لمحة سريعة

| العنصر | التفاصيل |
|---|---|
| نوع البرنامج | تطبيق ويب محلي (يعمل من المتصفح على `http://localhost:4000`) |
| قاعدة البيانات | ملف SQLite واحد: `HDANA.db` (بدون سيرفر قاعدة بيانات) |
| اللغات | العربية (RTL، افتراضي) + الإنجليزية (LTR) |
| العملة والمنطقة الزمنية | قابلة للضبط من الإعدادات (Timezone awareness كامل) |
| المرفقات والصور | تُخزَّن داخل ملف HDANA نفسه (لا ملفات شاردة) |
| التصدير | Excel حقيقي `.xlsx` + تقارير PDF عربية عبر مسار الطباعة |
| الصلاحيات | 4 أدوار (مدير النظام، مدير، محاسب، مشاهد) |
| النسخ الاحتياطي | يومي تلقائي + يدوي + استعادة بنقرة |
| التثبيت | `npm install` ثم `npm start` (Node.js ≥ 22.13) |

## 2) القرارات المعمارية (Architecture Decisions)

### 2.1 المعمارية المختارة
```
┌──────────────────────────── المتصفح (SPA) ────────────────────────────┐
│  index.html + ES Modules (بدون build step) + CSS Design System        │
│  Views: students · staff · revenue · expenses · finance · settings    │
└───────────────────────────────┬───────────────────────────────────────┘
                                │ REST /api  (JSON + raw uploads)
┌───────────────────────────────▼───────────────────────────────────────┐
│                    Node.js + Express 4 (خادم محلي واحد)                │
│  routes → services → db layer (node:sqlite)                           │
│  auth (bcrypt + sessions) · permissions · audit · daily scheduler     │
└───────────────────────────────┬───────────────────────────────────────┘
                                │ file system
                  ┌─────────────▼──────────────┐
                  │  HDANA.db  (SQLite + BLOBs) │  ← قلبه الوحيد للبيانات
                  │  storage/app-config.json    │  ← مسار الملف (الربط الدائم)
                  │  storage/backups/*.db       │  ← نسخ احتياطية
                  └────────────────────────────┘
```
* **لا خطوة Build** للواجهة: ملفات ES Modules تُخدم كما هي ⇒ تشغيل أسرع، صيانة أبسط، وبدء بلا مفاجآت.
* **الخادم محلي** ولا يحتاج إنترنت؛ الخطوط (Tajawal) مضمّنة داخل المشروع `public/assets/fonts`.

### 2.2 قاعدة البيانات
* **SQLite** عبر محرّك Node المدمج `node:sqlite` (بدون أي اعتماديات native) مع بديل تلقائي إلى `better-sqlite3` إذا لزم.
* الوضع `WAL` + `foreign_keys=ON` + `busy_timeout` لأداء وموثوقية عالية.
* ترحيلات (Migrations) تصاعدية محفوظة في `PRAGMA user_version`؛ لا تُعدَّل ترحيلات قديمة، تُضاف جديدة فقط.
* كل ملف HDANA يحمل بصمة `file_uuid` داخل جدول `meta` تُمكّن البرنامج من إعادة الربط بعد النقل.

### 2.3 إدارة الصلاحيات
* جلسات على الخادم: توكن عشوائي 32 بايت يُخزَّن **مُهشَّرًا** (SHA-256) في جدول `sessions`، ويُرسل في كوكي `HttpOnly` + `SameSite=Lax` لمدة 30 يومًا (دخول تلقائي).
* كلمات المرور: `bcrypt` (10 rounds) + سياسة حد أدنى 8 أحرف تحتوي حروفًا وأرقامًا.
* حماية CSRF: كل طلب تعديل يجب أن يحمل ترويسة `x-adamn-client: 1`، وحد محاولات دخول (lockout تدريجي).
* مصفوفة صلاحيات واحدة في `server/lib/auth.js` وتُستخدم في الواجهة والخادم معًا:

| الصلاحية | مدير النظام | مدير | محاسب | مشاهد |
|---|:--:|:--:|:--:|:--:|
| الطلاب (قراءة/كتابة/حذف) | ✔ | ✔ | قراءة + كتابة | قراءة |
| الموظفون | ✔ | ✔ | قراءة | قراءة |
| الرواتب | ✔ | ✔ | ✔ | — |
| إيرادات ومصروفات | ✔ | ✔ | ✔ | قراءة |
| المالية والتقارير | ✔ | ✔ | ✔ | ✔ |
| المستخدمون وإعدادات النظام | ✔ | جزئي | — | — |
| ملف البيانات والنسخ الاحتياطي | ✔ | — | — | — |

* سجل تدقيق `audit_log` لكل عملية حساسة (إنشاء/تعديل/حذف/دخول/تصدير/تغيير ملف البيانات).

### 2.4 تخزين المرفقات والصور
* الصورة والمرفقات تُحفظ **كـ BLOB داخل HDANA.db** (جدول `attachments`) وليس في ملفات منفصلة.
* السبب: ضمان قاعدة «انسخ ملف واحد فقط» وعمل النسخ الاحتياطي والاستعادة على كل شيء دفعة واحدة.
* الحدود: صورة الطالب ≤ 6MB، مرفق ≤ 18MB، مع فحص نوع MIME و SHA-256 واسم الملف المشفّر عند التنزيل.

### 2.5 تصدير Excel / PDF
* **Excel**: `exceljs` على الخادم ⇒ ملفات `.xlsx` حقيقية، أوراق RTL، رؤوس ملوّنة، صفوف إجماليات، تجميد رؤوس، AutoFilter.
* **PDF**: لكل تقرير مسار طباعة مُهيَّأ (`/print/students|student/:id|staff|payroll|revenue|expenses|finance`) مبني بـ HTML خطوط عربية مضمّنة.
  * القرار المتعمّد: لم نستخدم مكتبة PDF تُرسم بها الحروف العربية بشكل خاطئ؛ بدلًا من ذلك يُفتح التقرير ثم **«طباعة / حفظ كـ PDF»** من المتصفح ⇒ تشكيل عربي وRTL مثاليان وحجم A4 مضبوط. زر «تصدير PDF» في الواجهة يقوم بذلك تلقائيًا.
* الجداول والتقارير كلها قابلة للتصدير: الطلاب، بطاقة طالب، الموظفون، مسير الرواتب، سجل الرواتب، الإيرادات، المصروفات، المالية السنوية.

### 2.6 الوقت والتواريخ (Timezone-safe)
* **قواعد صارمة**:
  1. التواريخ المدنية (الميلاد، الالتحاق، تاريخ المصروف، الشهر `YYYY-MM`) تُخزَّن كنص `YYYY-MM-DD` / `YYYY-MM` ولا تُحوَّل أبدًا عبر Timezone.
  2. الطوابع الزمنية تُخزَّن `ISO-8601 UTC`، وتُعرض فقط عبر `Intl.DateTimeFormat` بالمنطقة الزمنية المضبوطة في الإعدادات.
  3. «اليوم» يُحسب دائمًا داخل المنطقة الزمنية المُعدّة، لا عبر `toISOString().slice(0,10)`.
* التحقق: `tests/time.test.js` يثبت أن `Africa/Cairo` في `22:30Z` يعطي يومًا مختلفًا عن `America/New_York`.
* الأعياد الميلادية (بما فيها 29 فبراير)، والعمر، ومدة الالتحاق، وحالة السداد لكل شهر — كلها محسوبة بهذه القواعد.

### 2.7 قاعدة البيانات التاريخية (لا تُعاد كتابة الماضي)
* رواتب الموظفين: جدول `staff_salary_rates` يسجّل **سعر الراتب الأساسي بتاريخ سريان**؛ رفع الراتب ينشئ سجلًا جديدًا ولا يغيّر الأشهر السابقة.
* كل شهر رواتب يُثبَّت في `staff_salaries` (basic / bonuses / rewards / deductions / net).
* اشتراكات الطلاب: صف لكل طالب/شهر في `student_payments`؛ التعديل لا يمسّ الشهور الأخرى. **الشهر الجديد يبدأ «لم يدفع» تلقائيًا** لعدم وجود صف له.
* التقارير المالية تُبنى من هذه السجلات التاريخية فقط.

## 3) التثبيت والتشغيل

### متطلبات مسبقة
* **Node.js 22.13 أو أحدث** (يحتوي `node:sqlite` المدمج) — من <https://nodejs.org>
* لا حاجة لأي قاعدة بيانات أو خادم إضافي.

### الأوامر (Installation)

```bash
# 1) الدخول لمجلد المشروع
cd AdamN

# 2) تثبيت الحزم (مرة واحدة)
npm install

# 3) (اختياري) بيانات تجريبية للتجربة — يمكن حذفها لاحقًا
npm run seed

# 4) تشغيل البرنامج
npm start
# ثم افتح المتصفح على:  http://localhost:4000
```

**تشغيل بنقرة واحدة:** `start.bat` (Windows) أو `./start.sh` (macOS/Linux) — يثبّت عند الحاجة، يشغّل الخادم، ويفتح المتصفح.

**أول تشغيل:** ستظهر شاشة إنشاء حساب مدير النظام (اسم المستخدم + كلمة مرور). إذا استخدمت `npm run seed` فالبيانات التجريبية تُنشئ:
`admin` / `AdamN2026` — **غيِّر كلمة المرور فورًا** من الإعدادات ← الأمان.

### أوامر أخرى

| الأمر | الوظيفة |
|---|---|
| `npm start` | تشغيل الخادم على `127.0.0.1:4000` |
| `npm run dev` | تشغيل مع إعادة تحميل تلقائي عند تعديل الخادم |
| `npm run seed` | بيانات تجريبية (تُتجاهل لو توجد بيانات) |
| `npm run seed -- --force` | إعادة توليد البيانات التجريبية |
| `npm test` | اختبارات الوحدات + اختبارات التكامل (39 اختبارًا) |
| `npm run doctor` | تشخيص البيئة وملف البيانات والنسخ الاحتياطي |
| `npm run reset -- --yes` | حذف ملف البيانات الحالي (ينشئ نسخة أمان أولًا) |

### متغيرات البيئة (اختيارية)
انسخ `.env.example` أو صدّر القيم:
```bash
HOST=127.0.0.1     # 0.0.0.0 لإتاحة الوصول من أجهزة الشبكة المحلية (تابلت/موبايل)
PORT=4000

ADAMN_OPEN=1       # فتح المتصفح تلقائيًا
```

## 4) ملف البيانات HDANA (الربط الدائم)

* **أين يوجد؟** افتراضيًا `storage/data/HDANA.db` داخل مجلد المشروع. يمكنك اختيار أي مسار آخر (مجلد على `D:\`، قرص شبكة، فلاشة…) من:
  **الإعدادات ← ملف البيانات HDANA ← إنشاء ملف بيانات جديد / ربط ملف آخر**.
* **بعد أول ربط** يُحفظ المسار في `storage/app-config.json` ⇒ يفتح البرنامج الملف **تلقائيًا في كل جلسة لاحقة** (لا يُطلب منك الاختيار مرة أخرى).
* **ماذا لو نقلت الملف؟** يكتشف البرنامج غياب الملف، يبحث في المجلدات الشائعة (المجلد السابق، المستندات، سطح المكتب، Downloads، Drive/OneDrive، جذور الأقراص) ويقارن **بصمة الملف `file_uuid`** فيعيد الربط تلقائيًا. يمكنك أيضًا الضغط على «بحث تلقائي عن ملفات HDANA».
* **نسخ احتياطي**: تلقائي يوميًا (قابل للإيقاف) + يدوي. الافتراضي `storage/backups/` مع الاحتفاظ بآخر 14 نسخة. كل نسخة تحمل بصمة الملف نفسها، ولذلك **لا يُربط البرنامج بنسخة احتياطية تلقائيًا** أبدًا.
* **الاستعادة**: من نفس الصفحة — يأخذ البرنامج نسخة أمان من الوضع الحالي ثم يستعيد النسخة المختارة.
* **نقل البرنامج لجهاز آخر**: انسخ مجلد المشروع + ملف HDANA (أو اختر مساره)، ثم `npm install && npm start` ثم «ربط ملف آخر» مرة واحدة.

## 5) الميزات بالتفصيل

### 5.1 الطلاب (تبويب أعلى الصفحة)
* تسجيل طالب: **اسم (حروف فقط)**، تاريخ ميلاد `dd/mm/yy` مع **حساب العمر فورًا**، تاريخ التحاق `dd/mm/yy` مع **مدة الالتحاق بالأيام والشهور والسنين**، **هاتف ولي الأمر (أرقام فقط)**، ولي الأمر، العنوان، ملاحظات، **قيمة الاشتراك الشهري**، **إطار صورة على يسار البيانات** مع زر رفع/تغيير الصورة.
* أزرار: **بحث، رفع مرفقات، حذف، تعديل، حفظ، معاينة وطباعة** (كل الطلاب أو طالب محدد).
* **قائمة أشهر السنة منسدلة** (تقف على الشهر الحالي تلقائيًا) + حقل مبلغ الشهر + ليبل: **المبلغ > 0 ⇒ «تم الدفع»**، و**0 ⇒ «لم يدفع»**. مع بداية شهر جديد يعود الجميع إلى «لم يدفع» تلقائيًا.
* طباعة طالب منفرد تعرض **كل شهور السنة** مع حالة كل شهر (مدفوع/لم يدفع) والمبلغ.
* جدول احترافي: صورة واسم، العمر، هاتف ولي الأمر، تاريخ الالتحاق، مدة الالتحاق، **مصفوفة 12 شهرًا** لحالة السداد (قابلة للنقر للتعديل)، الإجراءات.
* **Pagination + Sorting + Filtering + Search** (اسم / هاتف / حالة السداد / الشهر / السنة) + تصدير Excel + طباعة الجدول.
* المرفقات: رفع/تنزيل/حذف مستندات (PDF، صور، Word، Excel…) لكل طالب.

### 5.2 الموظفون
* إضافة/تعديل/حذف + تصدير Excel و PDF.
* الحقول: الاسم، الهاتف، الدور، تاريخ التوظيف، الراتب الأساسي (+ الحوافز، المكافآت، الخصومات على مستوى الشهر).
* **Net Salary = Basic + Bonuses + Rewards − Deductions** محسوب لحظيًا.
* **مسير رواتب شهري**: جدول قابل للتعديل لكل موظف (أساسي/حوافز/مكافآت/خصومات/الصافي/الحالة) مع حفظ كـ Snapshot لكل شهر.
* **سجل رواتب تاريخي** + سجل تعديلات الراتب الأساسي بتاريخ سريان (لا يتغيّر الماضي).

### 5.3 الإيرادات الأخرى
* الحقول: التاريخ، البيان، المبلغ، التصنيف، ملاحظات.
* تعديل/حذف + بحث + تصفية **باليوم/الشهر/السنة/نوع الإيراد** + تصدير Excel و PDF + بطاقات إجماليات.

### 5.4 المصروفات
* الحقول: التاريخ، البيان، المبلغ، التصنيف، ملاحظات.
* تعديل/حذف + بحث/تصفية + تصدير Excel و PDF.

### 5.5 المالية
* تجميع شهري لكل مصادر الدخل (اشتراكات الطلاب + إيرادات أخرى) والمصروفات (رواتب + مصروفات أخرى) وحساب **الربح/الخسارة** وهامش الربح.
* رسم بياني شهري، تفاصيل الشهر (توزيع الإيرادات والمصروفات، الطلاب الذين دفعوا، الرواتب).
* تنبيه بالرواتب غير المسجّلة (لا تُحتسب مصروفًا حتى تُسجّل).
* تصدير Excel + تقرير PDF.

### 5.6 مركز التنبيهات Notification Center
* **عيد ميلاد طالب غدًا** (مع العمر الجديد).
* **طلاب لم يدفعوا الشهر الحالي** + تنبيه **تجاوز موعد السداد** بعد يوم الاستحقاق.
* رواتب الشهر لم تُسجّل.
* بداية شهر جديد (تصفير حالة السداد).
* تنبيه مالي عند تسجيل خسارة في الشهر السابق.
* **Badge** بعدد غير المقروء في رأس الصفحة (تحديث تلقائي كل دقيقة)، تعليم الكل كمقروء، حذف المقروء.

### 5.7 الإعدادات
* عامة: اسم الحضانة، الهاتف، العنوان، **المنطقة الزمنية**، اللغة، العملة ورمزها، قيمة الاشتراك الافتراضية، يوم الاستحقاق، تصنيفات الإيرادات/المصروفات.
* ملف البيانات: المسار، الحجم، المحرك، البصمة، نسخ احتياطي/استعادة/اكتشاف/إنشاء/ربط.
* المستخدمون والصلاحيات (لمدير النظام) + إعادة تعيين كلمات المرور.
* الأمان: تغيير كلمة المرور + الجلسات النشطة وإلغاؤها.
* النظام: إصدارات، عدّادات السجلات، سجل المهام اليومية، تشغيل المهمة اليومية يدويًا.
* سجل العمليات (Audit Log).

### 5.8 المهام اليومية التلقائية
عند الإقلاع وكل 15 دقيقة يتحقق البرنامج: هل نُفّذت مهام اليوم في المنطقة الزمنية المضبوطة؟ إذا لا:
1. نسخة احتياطية يومية، 2. توليد التنبيهات، 3. تحديث `last_daily_run`، 4. تسجيل في `job_runs`.
كل التواريخ المحسوبة (العمر/المدة/الأعياد/الشهر الحالي) تُحسب عند القراءة ⇒ **صحيحة دائمًا** حتى بدون تشغيل البرنامج.

| المسار | الوصف |

## 9) الأمان والخصوصية
* كل شيء يعمل محليًا: لا يُرسل أي بيانات لأي خدمة خارجية، ولا توجد أي طلبات CDN (الخطوط والأيقونات محلية).
* كلمات المرور مُهشَّرة، الجلسات على الخادم وقابلة للإلغاء، حماية من CSRF وحد محاولات الدخول.
* ملف HDANA ملكك: انسخه، ضعه على قرص مشفّر أو في مجلد مزامنة… البرنامج يتعامل معه كملف واحد.
* سجل تدقيق كامل للعمليات الحساسة.

## 10) ملاحظات وحدود معروفة
* البرنامج مصمم لجهاز واحد/مستخدمين قليلين على نفس الجهاز أو نفس الشبكة المحلية (SQLite + WAL). لا تشغّل نسختين تكتبان في نفس الملف من جهازين مختلفين في نفس اللحظة.
* PDF يُنتج عبر محرك طباعة المتصفح لضمان تشكيل عربي سليم (زر «تصدير PDF» يقوم بذلك تلقائيًا).
* المرفقات تُخزَّن داخل الملف، فحجم HDANA يكبر بحجم المرفقات (النسخ الاحتياطي يشملها بالكامل).
